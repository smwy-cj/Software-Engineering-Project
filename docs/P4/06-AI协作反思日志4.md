## 2. AI助力分析（Q1）

**AI在编码中最有价值的场景：**

- 快速生成Spring Boot Controller、Service、Repository和DTO的样板结构。
- 根据P3 API规范补齐REST路径、请求字段和统一响应格式。
- 为Vue页面生成初版状态管理、表单校验、接口调用和错误提示。

**AI在测试生成中最有价值的场景：**

- 快速列出服务层核心边界，例如重复申请、自我申请、过期申请、未认证发布、重复评价。
- 生成集成测试的流程骨架，帮助覆盖注册、登录、发布、申请、审核和权限异常。
- 为前端补充低成本回归测试，例如路由守卫、JWT解析、本地存储容错和交互退化检查。

**AI在调试中最有价值的场景：**

- 对JWT、Spring Security、Maven、Vite等框架报错能快速给出候选原因。
- 能把异常栈和配置项关联起来，缩短“查文档和猜配置”的时间。
- 在给出完整上下文时，可以较快定位前后端字段名、路径和权限约定不一致的问题。

## 3. AI误导分析（Q2）

**AI代码信任度实验摘要：**

| 指标 | AI直出 | 人工修复后 |
|------|---------|------------|
| 编译 | 基本可通过 | 通过 |
| 登录正常路径 | 可用 | 可用 |
| 验证码与异常路径 | 不完整 | 可用 |
| 管理员权限 | 失败或不稳定 | 可用 |
| 后端测试 | 存在失败 | 51个用例通过 |
| 前端相关测试 | 未覆盖 | 16个用例通过 |

发现的主要问题：

- 安全逻辑容易被AI简化为固定值或占位实现。
- AI容易忽略Spring Security中 `hasRole` 与 `ROLE_` authority的细节。
- 对业务唯一性和并发边界，AI常给应用层检查，但缺少数据库约束兜底意识。
- 错误信息设计需要人工判断，避免暴露用户是否存在、权限结构等敏感信息。

**AI调试对决总结：**

- AI擅长：JWT密钥长度、角色前缀、路径匹配、构建配置等模式明确的问题。
- AI不擅长：重复申请、审核状态流转、禁言/封禁对不同模块的影响等需要业务上下文的问题。
- 典型问题：只修表象。例如重复申请场景中，AI建议Service层查重，但没有主动提出数据库唯一约束作为兜底。

## 4. Prompt改进计划（Q3）

**P3阶段改进措施验证结果：**

P3结束时提出“让AI同时读取API规范、ER图和详细设计”的策略在P4有效。相比只给自然语言需求，带上下文的Prompt能明显减少路径、字段和状态名不一致的问题。

**编码阶段Prompt最佳实践：**

1. 给出技术栈和版本：Spring Boot 3.2.5、JDK 17、Vue 3、Vite、Pinia、H2。
2. 给出接口约束：基础路径、认证要求、请求字段、响应包装。
3. 明确边界：哪些接口公开、哪些需要登录、哪些仅管理员。
4. 要求AI同时输出“异常路径”和“测试用例”，避免只覆盖Happy Path。
5. 对安全逻辑追加约束：不要泄露账号存在性，不要把验证码、权限、锁定策略写成TODO。

**调试阶段Prompt最佳实践：**

1. 同时提供报错、复现步骤、期望行为和相关代码。
2. 明确要求AI区分“可能原因”和“最小验证步骤”。
3. 对业务Bug追问：这个修复是否只在应用层有效，是否需要数据库、事务或权限兜底。
4. 修复后要求AI帮助补测试，但测试断言由人工审查。

**下阶段计划：**

- 为接口联调补充更完整的端到端测试脚本。
- 建立团队Prompt模板库，区分“生成代码”“代码审查”“调试定位”“补测试”“写文档”。
- 在PR合并前增加AI代码审查，但最终结论仍由团队人工确认。

## 5. 本阶段核心工程判断

**决策内容：**

团队决定暂缓P2智能匹配、实时聊天、统计看板、通用图片上传，集中完成P0/P1和测试闭环。

**为什么AI无法单独决策：**

- AI不知道团队真实可用工时、课程截止时间和演示评分重点。
- AI倾向补更多功能，但无法承担稳定性下降的后果。
- P2功能看起来有展示价值，但会引入额外接口、状态、存储和测试成本。

**团队最终取舍：**

1. 把找搭子、树洞、恋爱、通知、管理、反馈串成可演示主流程。
2. 每个主流程至少有一个自动化测试或回归测试支撑。
3. P2统一记录为后续迭代，不混入P4必交目标。
4. 文档按当前代码实现更新，明确哪些是已完成、哪些是限制或后续计划。

---

## 6. 阶段结论

AI在P4阶段显著提升了初稿生成、测试样例扩展和调试定位效率，但它不能替代工程判断。最终可靠性来自三件事：人工审查业务和安全边界、自动化测试验证、文档与代码保持一致。
