## 2. AI 助力分析（Q1）

**AI 在编码中最有价值的场景：**
- **大量重复性代码的快速生成**：20个JPA实体类、15个Repository接口在几分钟内生成完毕，人工编写需2-3小时
- **框架配置和样板代码**：Spring Security配置、JWT工具类、全局异常处理等，AI能快速给出可工作的基础配置

**AI 在测试生成中最有价值的场景：**
- **单元测试框架搭建**：AI能快速为Service方法生成Mockito测试结构，包括Mock对象注入和基本测试用例
- **边界条件提示**：AI会提示一些常见边界条件（如空值、重复值、过期时间等），帮助人工补充测试覆盖

**AI 在调试中最有价值的场景：**
- **配置类和框架层面Bug的快速定位**：JWT签名错误、Security路径匹配问题等，AI能基于错误信息秒级给出定位建议
- **错误信息的解释和翻译**：对复杂的框架报错信息，AI能给出通俗易懂的解释

## 3. AI 误导分析（Q2）

**"AI 代码信任度实验"数据摘要：**
- AI 直出的测试通过率：**67%**（2/3个核心测试通过）
- 人工审查修复后的测试通过率：**100%**（6/6全部通过）
- 发现的主要问题类型：
  1. 安全逻辑为空壳（短信验证码硬编码/未验证）
  2. 错误信息泄露敏感信息（区分用户不存在 vs 密码错误）
  3. 边界条件处理不完整（并发场景）

**"AI 调试对决"实验总结：**
- AI 擅长调试的 Bug 类型：**配置/签名/路径错误**（如JWT密钥长度、Security路径匹配）
- AI 不擅长调试的 Bug 类型：**业务逻辑Bug**（如并发绕过、需要理解完整业务流程的问题）
- AI 修复方案的典型问题：**"只修表象"**——建议应用层检查，但不考虑数据库层兜底约束等根因解决方案

## 4. Prompt 改进计划（Q3）

**上阶段改进措施的验证结果：**
上阶段（P3）提出的"提供完整上下文（代码文件+设计文档）而非仅描述需求"的策略在本阶段得到验证——当AI看到完整的API规范文档和建表SQL后，代码质量明显提升。

**编码阶段的 Prompt 最佳实践：**
1. **提供精确的技术约束**：如"使用BCrypt加密"、"JWT有效期2小时"、"Spring Boot 3.2.5 + JDK 17"
2. **提供参考文档路径**：让AI能对照P3设计文档生成符合规范的代码
3. **分步生成+逐步审查**：先让AI生成框架，再逐模块补充细节，比一次性生成全部代码质量更高

**调试阶段的 Prompt 最佳实践：**
1. **同时提供报错信息和相关代码文件**：只给报错信息AI容易猜测；给完整代码AI能准确定位
2. **描述复现步骤**：帮助AI理解Bug的触发条件
3. **说明期望行为 vs 实际行为**：AI能更准确地判断是否是Bug

**下阶段计划改进：**
- 尝试使用 AI 生成 API 集成测试（前端调用后端接口的端到端测试）
- 探索 AI 辅助代码审查（在 PR 合并前让 AI 识别潜在问题）
- 建立团队共享的 Prompt 模板库，减少重复编写 Prompt 的时间

## 5. 本阶段的核心工程判断

**决策内容：** P2 功能（智能匹配、管理后台统计、图片上传）全部降级，优先保证 P0/P1 功能完整和稳定

**为什么 AI 无法单独做这个决策：**
- AI 不了解团队的实际上课时间、考试安排和可用工时
- AI 不评估功能对课程成绩的影响权重
- AI 无法判断哪些功能是"演示必备"、哪些是"锦上添花"
- 这个决策需要权衡时间、质量、成绩等多维度因素，是典型的需要人工判断的工程取舍

**团队最终如何判断和取舍：**
1. 确认 P0 和 P1 共 14 个功能点的优先级排序
2. 评估剩余时间和人力：14 个功能点预计 34 小时，基本能在截止日期前完成
3. P2 功能明确标注为"暂缓"，如果时间有余量再考虑
4. 决策依据：保证核心演示流程的完整性和稳定性 > 功能数量的多少
